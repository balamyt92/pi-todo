# pi-todo

> ⚠️ **Это форк** оригинального пакета [`@juicesharp/rpiv-todo`](https://github.com/juicesharp/rpiv-mono/tree/main/packages/rpiv-todo) из монорепозитория [rpiv-mono](https://github.com/juicesharp/rpiv-mono). Полное сравнение с оригиналом — в разделе [«Что нового относительно rpiv-todo»](#что-нового-относительно-rpiv-todo) ниже.

Живая панель задач над редактором для [Pi](https://github.com/badlogic/pi-mono): модель планирует работу через тул `todo`, а вы видите прогресс в виджете. Главный пункт этого форка — **виджет умеет сворачиваться в одну строку** и разворачиваться обратно по команде или горячей клавише.

```
┌─ развёрнутый режим ────────────────────────┐   ┌─ свёрнутый режим ─────────────────────┐
│ ● Задачи (2/5)                            │   │ ▶ 2/7 [████████░░░░░░] 29% · #3 Пишу  │
│ ├─ ✓ написать схему                       │   │                                       │
│ ├─ ✓ покрыть тестами                     │   │ только счётчик, прогресс и текущая     │
│ ├─ ◐ написать README                     │   │ задача — минимум места над вводом       │
│ ├─ ○ собрать пакет                        │   └───────────────────────────────────────┘
│ └─ ○ опубликовать                         │
└───────────────────────────────────────────┘
```

## Установка

### Из git

```bash
pi install git:github.com/balamyt92/pi-todo@v1.0.2
```

Поддерживаются HTTPS и SSH:

```bash
pi install https://github.com/balamyt92/pi-todo@v1.0.2
pi install git:git@github.com:balamyt92/pi-todo@v1.0.2
```

### Из локальной папки (разработка)

```bash
pi install /path/to/pi-todo
```

После установки — `/reload` в сессии или перезапуск Pi.

### Если раньше стоял `@juicesharp/rpiv-todo`

pi-todo — самодостаточная замена: у него нет зависимостей от `rpiv-config` и `rpiv-i18n`, при этом **формат данных и имя тула сохранены**, так что старая история сессий проигрывается как есть. Оба пакета одновременно регистрируют тул `todo` и команды, поэтому старый пакет нужно убрать:

```bash
pi remove npm:@juicesharp/rpiv-todo
```

## Что нового относительно rpiv-todo

| | rpiv-todo | pi-todo |
|---|---|---|
| Режим виджета | только список | свёрнутый ⇄ развёрнутый |
| `/todos-toggle-widget` | — | есть |
| Горячая клавиша | — | `ctrl+shift+t` |
| Авто-сворачивание при завершении всех задач | — | есть |
| Изоляция состояний субагентов (общий процесс) | — | есть |
| Язык интерфейса | EN + опциональный i18n | RU |
| Внешние зависимости | `rpiv-config` | нет |

## Команды

### `/todos-toggle-widget`

Переключает виджет между свёрнутым и развёрнутым режимом.

```
/todos-toggle-widget            # переключить
/todos-toggle-widget collapse   # свернуть
/todos-toggle-widget expand     # развернуть
```

Аргументы дополняются по Tab. Когда задач ещё нет, виджет невидим, поэтому переключение подтверждается уведомлением.

### `/todos`

Развёрнутый список задач текущей ветки в чате, сгруппированный по статусам:

```
3/5 выполнено · 1 в работе · 1 ожидание
── Ожидание ──
  ○ #4 собрать пакет
── В работе ──
  ◐ #3 написать README (пишу README)
── Выполнено ──
  ✓ #1 написать схему
  ✓ #2 покрыть тестами
```

## Режимы виджета

### Развёрнутый

Заголовок `Задачи (выполнено/всего)` и список задач. Ёмкость — 12 строк; при переполнении сначала отсеиваются выполненные, хвост из незавершённых обрезается последним (и показывается сводка `+N ещё`).

### Свёрнутый

Одна строка:

```
▶ 2/7 [████████░░░░░░░░░░] 29% · #3 Пишу тесты
```

- `▶` — есть задача в работе, `○` — всё ещё в ожидании, `✓` — всё выполнено;
- `2/7` — выполнено/всего;
- прогресс-бар подстраивается под ширину терминала (8–28 символов);
- после `·` — текущая задача: взятная в работу, а если в работе ничего — первая незаблокированная.

### Авто-сворачивание

Как только все задачи выполнены, панель сворачивается сама. Если после этого развернуть её вручную (`/todos-toggle-widget` или хоткей) — обратно она не «захлопнется»: запрет снимается, когда появится новая незавершённая задача.

## Горячая клавиша

По умолчанию — `ctrl+shift+t`.

`ctrl+t` намеренно не используется: в Pi она занята под `app.thinking.toggle`. Смена клавиши — в одном месте, константа `TOGGLE_SHORTCUT` в `types.ts`.

## Тул `todo`

Схема и семантика совместимы с rpiv-todo:

```ts
todo({
  action: "create" | "update" | "list" | "get" | "delete" | "clear",

  subject?: string,               // обязательно для create
  description?: string,
  activeForm?: string,            // «что делаю сейчас», видно в in_progress
  owner?: string,
  metadata?: Record<string, unknown>,  // null по ключу удаляет его при update

  blockedBy?: number[],           // стартовые зависимости (create)
  addBlockedBy?: number[],        // аддитивное добавление (update)
  removeBlockedBy?: number[],     // аддитивное удаление (update)

  id?: number,                    // для update / get / delete
  status?: "pending" | "in_progress" | "completed" | "deleted",
  includeDeleted?: boolean,       // только для list
})
```

Переходы статусов: `pending ⇄ in_progress`, любой → `completed`, любой → `deleted` (терминальный). `deleted` — tombstone, чтобы исторические ссылки `blockedBy` не «повисали». Циклы в зависимостях отклоняются на уровне редьюсера.

Состояние переживает `/reload` и компакцию разговора: оно восстанавливается из последней записи тула в ветке, а не с диска.

## Изоляция по сессиям (субагенты)

Субагентские расширения (например, `@tintinweb/pi-subagents`) спавнят агентов
в том же процессе, что основная сессия, и привязывают к дочерним сессиям тот
же модуль расширения. Без изоляции задачи субагентов смешивались бы со списком
основной сессии: основной агент видел бы чужие задачи в своих ответах `list`,
а `clear` субагента уничтожал бы родительский список.

pi-todo хранит состояние отдельно для каждой сессии — под ключом
`sessionManager.getSessionId()`:

- **Виджет и `/todos` показывают только основную (UI-)сессию.** Задачи,
  которые субагент создаёт через `todo`, в него не попадают.
- **Субагенты работают со своими списками.** У каждого субагента свой
  полноценный `todo`: он не видит и не трогает списки других сессий.
- **События субагентов не дёргают виджет.** Перерисовка, сброс режима и
  скрытие выполненных задач привязаны к событиям UI-сессии.
- **Ключи дочерних сессий очищаются** при их завершении (`session_shutdown`),
  чтобы Map не рос на каждый спавн.

UI-сессия определяется на `session_start` с `hasUI` — это та сессия,
которой принадлежит терминал. При переключении сессии (`/resume`, новая
сессия) указатель переезжает на неё, и виджет показывает её список.

## Разработка

```bash
npm install         # зависимости для типов и тестов
npm test            # node --test tests/*.test.ts
npm run typecheck   # tsc --noEmit
```

Структура:

```
index.ts        точка входа: регистрация тула, команд, хоткея, события сессии
types.ts        доменные типы, схема параметра, константы (в т.ч. TOGGLE_SHORTCUT)
reducer.ts      чистый редьюсер: валидация, переходы, операции
invariants.ts   таблица допустимых переходов статусов
graph.ts        циклы в blockedBy, обратная смежность (blocks)
store.ts        живое состояние, изолированное по сессиям (Map по sessionId)
replay.ts       восстановление состояния из ветки сессии
selectors.ts    счётчики, «текущая задача», компоновка при переполнении
format.ts       глифы, строки списка, прогресс-бар, свёрнутая строка
overlay.ts      контроллер виджета: режимы, авто-сворачивание
tool.ts         регистрация тула todo
commands.ts     /todos и /todos-toggle-widget
tests/          69 тестов на чистую логику (node:test, без внешних зависимостей)
```

Тесты покрывают редьюсер, селекторы, форматирование, поведение виджета
(переключение режима, авто-сворачивание, «замок» после ручного разворота),
регистрацию расширения и изоляцию состояний по сессиям (субагенты).

## Публикация

```bash
npm publish         # required: keyword "pi-package" уже в package.json
```

Пакет помечен `"pi": { "extensions": ["./index.ts"] }`, поэтому Pi подхватывает его и из npm, и из git без дополнительной конфигурации.
